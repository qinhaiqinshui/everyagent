# 计划模式

## 适用条件
- 当任务足够复杂、需拆成多个步骤来执行时，使用本技能。
- 用户明确要求使用计划模式，或者让你做计划，也可以使用本技能。
- 如果用户任务非常简单，那么直接输出结果即可，不分步骤执行，并且告诉用户不适合使用计划模式的原因。

## 计划文档

### 计划内容存储
每个计划由你生成「人类可读的计划名称（planName）」，并保存计划文档。文件名与存放位置均不强制约束，由你根据当前环境自行决定（建议文件名形似 `plan-<name>.md`，`<name>` 为该计划名称的安全化写法，只保留字母、数字、连字符与中文；同一任务内不同计划取不同名称，避免互相覆盖）。

### 计划文档结构（推荐模板）
一份计划文档建议包含以下部分，便于你和用户随时掌握全貌：

```markdown
# <计划名称>

## 目标
<一句话说明要达成什么>

## 步骤
- [ ] 步骤 1：<步骤描述>
    - 状态：待执行
    - agent：-
    - 依赖：无 / 依赖步骤 N
    - 验收标准：<该步骤完成的判定条件 / 可见结果>
- [ ] 步骤 2：<步骤描述>
    - 状态：待执行
    - agent：-
    - 依赖：依赖步骤 1
    - 验收标准：<...>

## 备注
<依赖关系、可并行说明、已知约束、回退方案>
```

每个步骤务必留出 **状态** 与 **agent** 两个字段——这是「进度更新」与「续跑」的关键落点。

### 计划内容示例
以「撰写小说某一章」为例，一份已经派发两步的计划文档长这样：

```markdown
# 撰写《玄幻三国》第一章

## 目标
完成第一章正文（约 3000 字），拆分为大纲、引言、正文三步走。

## 步骤
- [x] 步骤 1：拟写本章大纲
    - 状态：已完成
    - agent：`sess-3f9a2c1b`
    - 依赖：无
    - 验收标准：内容保存到`ch1-outline.md`文件
- [~] 步骤 2：写引言段落
    - 状态：进行中（已派发）
    - agent：`sess-7b21e44d`
    - 依赖：无
    - 验收标准：引言内容（追加进 `ch1.md`）
- [ ] 步骤 3：写正文主体
    - 状态：待执行
    - agent：-
    - 依赖：依赖步骤 2 的引言
    - 验收标准：完成正文主体编写

## 备注
步骤 2、3 串行：步骤 3 需引用步骤 2 的引言，故不可并行。
```

### 计划步骤划分规则
- 每一个步骤只做一件事。
  — 如果是修正已有问题，则每一个步骤只修正一个问题，有多少个问题就有多少个步骤。
- 如果任务的核心是内容撰写，且是长内容编写、更新、保存，则必须分多步骤输出，每次只新增、更新一个段落，不可一个步骤里将所有内容保存。
- 步骤之间若存在依赖（先后读写同一份中间产物、后一步需前一步的结果），则必须串行执行。
- 彼此无依赖、互不读写同一中间产物的步骤，可并行执行。

### 计划文档使用规则
- **先出计划、再执行**：在派发任何步骤之前，先把计划写入文件，让用户和执行链都有据可查。
- **派发即记录**：每派发一个步骤，立即把该步状态改为「进行中」并把返回的 `agentId` 写回对应步骤旁（见「进度更新」）。
- **计划文件是「继续」的唯一真相源**：刷新 / 中断 / 重试后，都从计划文件读回旧 `agentId` 续跑，不要凭记忆重建。
- **一份文件一份计划**：当前上下文中可能有多份计划文件（`plan-A.md` / `plan-B.md` …），每份用不同计划名称与文件名区分；切换计划时以文件名明确指代，不要混写。
- **只记索引不塞正文**：计划文件只记录「做了什么 / 谁在做（agentId） / 做到哪一步 / 产出在哪」，不要把子 Agent 的完整输出塞进计划文件。

### 进度更新
- 每派发一个步骤，把返回的 `agentId` 记到该步骤旁，并同步该步骤状态（待执行 / 进行中 / 已完成 / 失败）。
- 步骤完成后（确认其运行结果为终态），把对应步骤标记为「已完成」，并视情况更新 `验收标准` 字段、把产物路径写进计划文档。
- 步骤失败后重试 / 续跑，同样要把结果与状态写回计划文档。


## 执行方式
- 默认只按照用户需求产出计划方案，由用户确认后再执行；如果用户提交了新的修改则你也只是修改方案内容，不可擅自按计划执行，除非用户说明在产出计划方案后立即执行。
- 计划的派发执行依赖「子 Agent 编排」技能：执行前先读取该技能的详细说明，再按其中的工具与规则派发、等待、停止、续跑子 Agent。本技能不重复描述这些工具。
- 有依赖的步骤串行派发；无依赖的步骤可并行派发，全部派发完再统一收集结果。
- 每次派发子 Agent，都只派发计划步骤中的一个步骤，不能同时派发多个步骤给一个 Agent。
- 你必须作为主Agent负责派发子Agent 和结果审查。由你来按照验收标准验收，若验收不通过则由你让对应的子Agent修改直到符合验收标准。
